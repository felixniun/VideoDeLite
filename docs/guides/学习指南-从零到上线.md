## 1. 项目是什么

**VideoDelite** = Windows 桌面视频压缩工具 + 账号授权服务端。

```
桌面客户端（你电脑上跑的 .exe）
   ├── 界面：Vue 3（网页技术做的桌面界面）
   ├── 核心：Go 语言 + FFmpeg（真正干压缩活的程序）
   └── 打包：Wails 框架（把网页和 Go 打包成一个 exe）

服务端（跑在 Linux 服务器上）
   ├── Go HTTP 服务：注册/登录/设备激活/授权
   ├── 数据库：SQL Server
   ├── 邮件：Resend API 发验证码
   └── 反代：nginx + HTTPS 证书
```

**核心原则（架构红线）**：视频永远留在用户电脑上，服务器只管"你是谁、有没有权限"。
压缩用的 FFmpeg 代码和账号代码**物理隔离**在不同的目录，互不依赖 —— 这是本项目
最重要的设计决策，防止未来有人图省事把两个系统搅在一起。

## 2. 技术栈速查表

| 层 | 技术 | 为什么选它 |
|---|---|---|
| 桌面框架 | Wails v2.16.0 | Go 原生打包桌面应用 |
| 前端 | Vue 3 + TypeScript + Vite | 主流、类型安全、热重载快 |
| 后端语言 | Go | 编译成单文件、跨平台、并发强 |
| 媒体处理 | FFmpeg / FFprobe | 视频领域事实标准 |
| 客户端数据库 | SQLite（modernc.org/sqlite 纯Go驱动） | 免安装、单文件 |
| 服务端数据库 | SQL Server 2022（Docker Compose） | 仓库当前部署模板使用 SQL Server |
| 密码哈希 | Argon2id | 2026 年的行业标准 |
| 登录凭证 | JWT(15min) + Refresh Token(30天轮换) | 无状态 + 可撤销 |
| 凭据存储 | Windows 凭据管理器 | 不在文件里存明文 |
| 邮件 | Resend HTTP API | 免费额度够用、域名校验防伪造 |
| HTTPS 证书 | Let's Encrypt（acme.sh DNS-01） | 免费、自动续期 |
| 部署 | Docker Compose（Debian） | 一键迁移、环境一致 |
| 安装包 | NSIS | Windows 免费方案 |

## 4. 问题实录（现象 → 根因 → 解决 → 学到什么）

这是全文最有价值的部分。每个问题都是真实踩过的坑。

### 4.1 环境类

#### ① 依赖下载超时
- **现象**：`go install` / `npm install` 卡死超时
- **根因**：国内访问 Google/GitHub 被墙
- **解决**：`GOPROXY=https://goproxy.cn,direct`；npm 换淘宝源；Docker 镜像加速
- **学到**：国内开发第一件事就是配代理，不是等它慢慢下载

#### ② Docker 拉镜像超时（`failed to fetch anonymous token`）
- **现象**：服务器上 `docker compose build` 卡在拉基础镜像
- **解决**：`/etc/docker/daemon.json` 配 `registry-mirrors`；Dockerfile 里 `GOPROXY` 也要设
- **学到**：Docker 构建有**两层**网络依赖——拉基础镜像 + 构建内下载依赖，都要处理

### 4.2 数据库类（SQL Server 与 SQLite 的 5 个差异）
> 教训：开发用 SQLite，生产用 SQL Server，**一定要在真实数据库上联调**。
> 单元测试全过 ≠ 生产能跑。本项目 5 个 bug 全是联调时暴露的。

#### ③ `Incorrect syntax near '?'`
- **根因**：go-mssqldb 不支持 `?` 占位符（SQLite 支持），要求 `@p1, @p2...`
- **解决**：写一个占位符重写层，执行前把 `?` 按序号转成 `@pN`（`server/placeholders.go`）
- **学到**：不同数据库驱动对同一 SQL 方言的支持差异，用**统一封装层**吸收

#### ④ `Incorrect syntax near 'OUTPUT'`
- **根因**：取自增 ID，SQLite 用 `RETURNING id`（放句尾），T-SQL 的 `OUTPUT INSERTED.id` 必须放在 `VALUES` **之前**
- **学到**：同一种功能在不同数据库的语法位置都可能不同；封装时用正则定位插入点要容忍换行

#### ⑤ `LIMIT` 不存在
- **根因**：T-SQL 没有 `LIMIT`，要用 `OFFSET 0 ROWS FETCH NEXT ? ROWS ONLY`
- **学到**：分页是方言重灾区

#### ⑥ 查询结果"找不到"（实际数据存在）
- **根因**：MSSQL 的 `DATETIME2` 列扫描出来是 Go 的 `time.Time`，而代码用 `string` 接 → Scan 报错被上层误报为"not found"
- **解决**：所有时间列用 `any` 接，统一 `toTime()` 归一化
- **学到**：**错误被上层吞掉并转译成误导性信息**是调试最大的敌人；报错要保留原始信息

#### ⑦ BIT 列扫描失败
- **根因**：MSSQL BIT → Go `bool`，SQLite → `int64`；用 `int` 接 MSSQL 的 bool 直接失败
- **附带发现**：`any != 0` 对 bool 恒为 true 的语义陷阱（`bool(false) != int(0)` 因类型不同而相等性为 false → 结果 true）
- **学到**：接口类型与具体值的比较要小心动态类型

### 4.3 桌面应用类

#### ⑧ 弹出黑色终端框 0.5 秒
- **现象**：拖入视频或点压缩时闪一下黑框
- **根因**：Windows 上 `exec.Command` 启动控制台程序默认创建控制台窗口
- **解决**：统一封装 `proc.Command()`，设 `SysProcAttr{HideWindow:true, CreationFlags:0x08000000(CREATE_NO_WINDOW)}`
- **学到**：GUI 程序里所有子进程调用都要过统一封装，散落的 `exec.Command` 就是隐患

#### ⑨ 主题切换不生效 / 密码框白条
- **根因1**：主题按钮只改了本地变量，没调用应用函数
- **根因2**：CSS 只覆盖了 `input[type=text]`，password 用了浏览器默认样式
- **解决**：即时应用 + CSS 补 `input[type=password]` 和 `color-scheme: dark`（后者让原生下拉框也变深色）
- **学到**：WebView 类应用中，**原生控件**（下拉、日期选择）跟随 `color-scheme` 而非你的 CSS

#### ⑩ GPU 编码崩了但没有任何报错
- **现象**：x265 编码进程退出码 -22，stderr 干净
- **排查**：二分法替换参数 → 对照测试 plain exec vs CREATE_NO_WINDOW → 最后发现是重复传了两次 `-x265-params`
- **学到**：exit code 不是 0 且无输出时，把完整命令行打出来手动跑一遍是最快的定位法

### 4.4 媒体处理类

#### ⑪ HDR10 标记丢失（QA 矩阵发现）
- **现象**：源是 HDR10，压出来 trc 变 unknown
- **根因**：`ffmpeg -color_trc smpte2084` 这类输出选项**不会传导给 libx265 的 VUI**，必须用 `-x265-params colorprim=bt2020:transfer=smpte2084:colormatrix=bt2020nc`；而 NVENC 会自动从输入帧继承
- **解决**：CPU 路径额外追加 `-x265-params`
- **学到**：FFmpeg 的全局选项 ≠ 编码器私有参数；QA 矩阵（自动生成源→自动对比）让这类问题无处藏身

#### ⑫ 进程孤儿锁死临时文件
- **现象**：强杀主程序后，ffmpeg 子进程还活着，临时目录被锁住删不掉
- **解决双管齐下**：
  1. **Job Object**（Windows 内核机制）：子进程加入 `KILL_ON_JOB_CLOSE` 的 Job，主进程死亡 OS 自动杀子进程
  2. **启动清扫**：程序启动时删除上次残留的临时目录
- **学到**：父子进程生命周期绑定是桌面应用的基本功；"启动时清理"是兜底，"机制保证"是根本

### 4.5 网络与部署类（本项目最大的坑集中区）

#### ⑬ DNS 解析到旧 IP（改了记录不生效）
- **现象**：Cloudflare 面板把橙云改灰云（指向真实服务器 IP），但部分用户解析到旧的 CF IP
- **诊断**：分别问不同 DNS（`nslookup domain 8.8.8.8` / `223.5.5.5` / 直接问权威 NS）→ 权威已正确，只是某些 ISP DNS 缓存长（无视 TTL）
- **解决**：affected 主机改公共 DNS 或写 hosts
- **学到**：**DNS 变更 ≠ DNS 生效**。排查 DNS 问题要分层：本机缓存(`ipconfig /flushdns`) → 递归 DNS → 权威 DNS（`nslookup domain 权威服务器地址` 直接问）

#### ⑭ 运营商封端口（家宽建站终极 boss）
- **现象**：ping 公网 IP 通（0% 丢包），但 TCP 80/443/8080/8443 全部超时
- **诊断**：先测一个**已知能用的转发端口**做对照（本项目是 minecraft 的 61111，0.2s 可连）→ 证明转发机制正常、只有 Web 端口段被封 → 结论：国内家宽 ISP 封 80/443/8080/8443 入站
- **解决**：HTTPS 换到高位端口 28443（CF 支持的备用 HTTPS 端口之一）；证书用 **DNS-01 验证**签发（不需要任何入站端口）
- **学到**：
  - ping 通 ≠ 端口通（ICMP 和 TCP 是两回事）
  - 对照实验是定位"哪一层坏了"的利器：已知好的端口 vs 坏的端口
  - 证书签发（DNS-01）和 HTTPS 服务（监听端口）是两件独立的事

#### ⑮ NAT 回环（内网访问自己的域名失败）
- **现象**：外网访问域名正常，公司内网电脑访问同一域名超时
- **根因**：内网电脑访问公网 IP 时，流量出路由器再回来（hairpin NAT），多数家用/企业路由器不支持
- **解决**：内网主机 hosts 写死 `192.168.100.101 域名`，流量直达服务器不经过路由器
- **学到**：内外网用户要"同一个域名同一个端口"，就要分别保证两条路径都通；hosts 是内网最简单可靠的方案

#### ⑯ Cloudflare 522 错误
- **现象**：橙云代理下访问报 522（CF 连不上源站）
- **关联**：522 = CF（境外）→ 源站（国内家宽）回源失败。结合 ⑭ 的端口封禁，橙云对"国内家宽自建服务"基本不可用，除非源站端口在 CF 备用端口列表且 ISP 未封
- **学到**：CDN 代理（橙云）需要源站对 CDN 可达；源站在被限网络里时，Tunnel（出站）或灰云直连才是出路

#### ⑰ SSL 证书怎么签（80 被封时）
- **方案**：Let's Encrypt 支持 DNS-01 验证 —— 不需要任何入站端口，通过给域名加 TXT 记录证明所有权
- **工具**：acme.sh（国内用 gitee 镜像装）+ Cloudflare API Token（自动加 TXT + 自动续期）
- **部署**：`acme.sh --install-cert` 把证书装到 nginx 目录，`--reloadcmd` 在续期后自动 reload nginx
- **学到**：HTTP-01（需要 80 端口）和 DNS-01（需要 DNS API）是两条独立路径，端口被封时用后者

### 4.6 服务端部署类

#### ⑱ SQL Server 容器密码改了不生效
- **根因**：`MSSQL_SA_PASSWORD` **只在数据卷首次初始化时生效**，密码写进 master.mdf 后改环境变量无效
- **解决**：改密码 = 改环境变量 + `docker volume rm` 删卷重建（有数据先备份）
- **学到**：有状态容器的"初始化参数"是一次性的；区分"配置"和"数据"

#### ⑲ SA 登录失败 18456（密码不一致）
- **根因**：compose 里 db 容器的密码与服务端连接串的密码写了两个不同的值（人为笔误）
- **预防**：密码这类多处引用的值，用 compose 的 YAML 锚点或 .env 统一
- **学到**：容器编排里"同一个值写两处"早晚出错

#### ⑳ Docker 网络被占用无法重建
- **现象**：`network has active endpoints (name:"whoami")` 
- **解决**：无关容器挂在共享网络上时，新 compose 不要引用同名网络；本项目反代直接用默认 bridge + `172.17.0.1` 访问宿主端口
- **学到**：容器访问宿主机端口的写法是 `172.17.0.1:端口`（docker0 网关）

## 5. 上线部署清单（Debian 实操）

### 5.1 服务端（Docker Compose）

```bash
# 上传项目（需要 go.mod go.sum cmd/ server/ internal/ Dockerfile docker-compose.yml）
sudo docker compose up -d --build
# 首次会：拉镜像 → 建库建表 → 服务监听 8800
sudo docker compose ps          # 两个容器 healthy
curl http://127.0.0.1:8800/api/v1/version
```

### 5.2 HTTPS（nginx-proxy + acme.sh）

```bash
# 1. nginx 容器映射 28443:443，conf.d 配两个域名
# 2. 签证书（DNS-01，需要 CF Token）
sudo /root/.acme.sh/acme.sh --issue --dns dns_cf \
  -d videodelite1.898280.xyz -d videodelite.898280.xyz --server letsencrypt
# 3. 安装证书 + 自动续期钩子
sudo /root/.acme.sh/acme.sh --install-cert -d videodelite1.898280.xyz \
  --fullchain-file .../certs/fullchain.pem --key-file .../certs/key.pem \
  --reloadcmd "docker exec nginx-proxy nginx -s reload"
```

### 5.3 网络（本次部署的坑全集）

| 步骤 | 内容 |
|---|---|
| 路由器端口转发 | 外部 28443 → 192.168.100.101:28443（TCP） |
| CF DNS | A 记录指公网 IP，**灰云**（橙云回源被 ISP 封端口挡住） |
| 内网 hosts | `192.168.100.101 两个域名`（绕 hairpin） |
| 证书验证 | acme.sh DNS-01（80 被封不影响） |

### 5.4 排障工具箱（背下来）

| 症状 | 命令/方法 |
|---|---|
| 端口通不通（外部视角） | check-host.net / itdog.cn / 手机流量直连 |
| DNS 指向哪 | `nslookup 域名 8.8.8.8`（绕本机缓存）；问权威：`nslookup 域名 权威NS地址` |
| 容器日志 | `docker compose logs --tail 30 server` |
| 服务端活没活 | `curl -m 3 http://127.0.0.1:8800/api/v1/version` |
| 证书信息 | 浏览器 F12 安全页 / `curl -vI https://域名` |

## 6. 安全备忘（上线前必读）

1. **改默认密码**：SQL SA、管理后台 adminKey、Resend Token 全部换强随机值
2. **密码不一致是大坑**：compose 里 db 密码和连接串密码用 `.env` 或锚点统一
3. **凭据别进 git**：config.json、*.pfx、jwt.secret 都在 .gitignore
4. **Token 最小权限**：CF Token 只给 Zone.DNS Edit；API Key 只给发信权限（本项目 Key 就是 send-only，查不了账户信息，反而安全）
5. **泄露轮换**：任何出现在聊天/截图里的密钥都应轮换

## 7. 给下一个项目的建议清单

- [ ] 第一天就配好 GOPROXY / npm 源 / Docker 镜像加速
- [ ] 每个阶段结束做一次真实运行验证（不是 mock）
- [ ] 数据库方言差异用统一封装层吸收；**联调必须用生产同款数据库**
- [ ] 子进程创建统一封装（GUI 隐藏窗口、Job Object 绑生命周期）
- [ ] QA 用"生成测试源 → 自动对比"的矩阵，不靠人眼
- [ ] 强杀进程的崩溃恢复测试必做（Job Object + 启动清扫）
- [ ] 上线前用外部探测点验证端口和 DNS（check-host.net / itdog.cn / 手机流量）
- [ ] DNS 变更后分层排查：本机缓存 → 递归 DNS → 权威 DNS
- [ ] 家宽建站：先测 ISP 封了哪些端口（用已有可用的转发端口做对照），再定 HTTPS 端口
- [ ] 80 被封时用 acme.sh DNS-01 签证书，服务监听高位端口
