# VideoDelite 文档

这里按用途整理产品规格、开发指南、部署说明和验证报告。README 介绍当前代码库与开发入口；本页汇总业务模型，并说明不同文档的用途。

## 核心业务模型

VideoDelite 面向 Windows 用户，提供本地视频压缩与转码。产品闭环是：

```text
导入视频 → 本地媒体分析 → 配置编码 → 本地任务队列 → FFmpeg 编码 → FFprobe 验证 → 本地历史
```

产品设计遵循以下边界：

- **视频处理在本地完成。** 视频内容、文件名、路径、媒体元数据、编码命令和压缩结果不发送到账号服务器。
- **Simple 模式无需账号。** 用户可使用 H.264 / H.265、画质档位、MP4 / MKV、硬件编码或 CPU 回退。
- **输出必须通过校验。** FFmpeg 返回成功并不等于任务成功；应用还会用 FFprobe 检查生成文件。
- **授权与编码相互隔离。** 授权影响 Professional 新任务的创建，不应中断已运行的本地编码任务。
- **本地数据留在本机。** 设置、历史和日志不做自动同步或遥测上传。

## 当前实现状态

产品规划和历史交付记录描述了不同阶段，不能把计划当成当前可用状态。当前 checkout 的授权状态默认从 `UNAUTHENTICATED` 开始；前端提示 Professional 许可尚未开放。因此，日常使用说明以根目录 [README](../README.md) 和当前代码为准，Professional 功能在许可流程可用前仍视为受门控。

《MVP 交付计划书》和《从零到上线学习指南》是 2026-10-04 的阶段性记录，其中有些交付状态和技术版本早于当前代码。它们保留为项目历史与决策背景；产品意图以产品计划和边界规范为准，当前行为以代码为准。
